# النسخ الاحتياطي

## حالة التفعيل

هذه الميزة غير مفعّلة افتراضيًا. تطويرها على dev لا ينشئ نسخًا من قاعدة اللايف ولا يغيّرها. لا تضبط إعدادات prod أو اتصال العامل باللايف قبل موافقة المستخدم.

الواجهة /backups، رابطها أسفل النظام بالجانب اليمين، وواجهات API تتحقق من دور admin الحالي في قاعدة البيانات عند كل طلب. لا يكفي امتلاك صلاحية إدارة المستخدمين. الملفات مشفرة AES-256-GCM، ولا يوجد زر استرجاع أو حذف يدوي.

## بنية التشغيل

خادم الويب يتصل بعامل مستقل عبر HTTPS مع رمز سري. العامل عملية Node دائمة واحدة، تعمل على مضيف منفصل مع قرص دائم خاص وتخزين مشفر على مستوى المضيف. لا تشغله كـVercel Function ولا تحفظ الملفات على قرص Vercel المؤقت. هذا الفصل يسمح باستمرار النسخ بعد إغلاق الصفحة. يلزم توفير المضيف والقرص؛ الكود لا ينشئهما تلقائيًا. استخدم نسخًا/تكرارًا للقرص في منطقة أخرى إذا كان مطلوبًا تحمّل فقد المضيف نفسه.

العامل يستخدم pg_dump لنسخة متسقة تشمل schema public (جداول النظام وبياناتها بما فيها المستخدمون وكلمات المرور المشفرة والصلاحيات). لا يشمل ملفات Supabase Storage أو Auth المدار من Supabase، أو إعدادات البنية التحتية، أو متغيرات البيئة. تغيّر الجداول ضمن public يدخل في النسخ تلقائيًا.

## متغيرات عامل التشغيل (أسرار خارج git)

- BACKUPS_ENABLED=true: موافقة تشغيل صريحة، لا تُضبط أثناء تجربة dev مع قاعدة اللايف.
- BACKUP_DATABASE_URL: اتصال PostgreSQL معتمد للنسخ، direct أو session pooler، لحساب يستطيع قراءة كل جداول public. لا يوجد fallback إلى DATABASE_URL.
- BACKUP_DIRECTORY: مسار مطلق لقرص دائم خاص على المضيف المنفصل؛ لا يكون تحت public أو مجلد المستودع.
- BACKUP_ENCRYPTION_KEY: مفتاح عشوائي 32 بايت بصيغة hex. احفظه خارج مضيف النسخ في مدير أسرار؛ فقده يمنع الاسترجاع. لا تغيّره بدون الاحتفاظ بالمفتاح السابق.
- BACKUP_WORKER_TOKEN: رمز عشوائي بطول 32 حرفًا على الأقل.
- BACKUP_WORKER_HOST: افتراضي 127.0.0.1 خلف reverse proxy يدعم HTTPS.
- BACKUP_WORKER_PORT: افتراضي 3101.

ثبّت pg_dump من PostgreSQL بنفس إصدار الخادم أو أحدث ومتوافق، وNode 22+ وتبعيات المشروع. شغّل `node scripts/backup-worker.js` عبر مدير خدمات مع إعادة تشغيل تلقائية وبيئة أسرار مخصصة. لا تقرأ .env الخاص بالموقع تلقائيًا.

العامل يرفض التشغيل إذا وجد worker.lock. بعد تعطل حقيقي تحقق من توقف العملية القديمة ثم أزل القفل فقط قبل إعادة التشغيل. لا تشغّل نسختين بنفس المجلد. تُعلَّم العمليات المنقطعة كفاشلة عند الإقلاع وتزال ملفاتها المؤقتة.

## متغيرات الموقع

- BACKUPS_ENABLED=true
- BACKUP_WORKER_URL=https://your-private-backup-worker.example
- BACKUP_WORKER_TOKEN=نفس رمز العامل

يمكن استخدام http://127.0.0.1:3101 للتجربة المحلية فقط. لا تضع الرمز في المتصفح. عدم وجود الإعدادات يعرض حالة «غير مفعّل»، وتعطل العامل يعرض خطأ اتصال ولا يعرض سجلًا ناجحًا وهميًا.

## الجدولة والاحتفاظ

كل الأوقات في الصفحة بتوقيت الرياض UTC+3. أول موعد هو أقرب وقت قادم؛ التالي بعد 1 أو 7 أو 14 يومًا. العامل يفحص كل دقيقة، ويشغّل موعدًا متأخرًا مرة واحدة عند عودته. لا ينشئ عدة نسخ لتعويض توقف طويل. إذا فشلت النسخة يُحفظ الخطأ ويمكن إعادة المحاولة يدويًا؛ لا توجد إشعارات خارج الصفحة حاليًا. النسخ اليدوي لا يغيّر موعد الجدولة.

عند نجاح نسخة تُحذف الملفات المكتملة المنتهية حسب مدة الاحتفاظ، مع إبقاء أحدث نسخة وأي نسخة معلّمة للاحتفاظ. السجل يبقى ويظهر «انتهت مدة الاحتفاظ». تغيير المدة يطبق عند نجاح النسخ التالية.

## التحقق والاسترجاع

الاختبارات المحلية تستعمل ملفات وهمية ومجلدات مؤقتة؛ لا تصل إلى اللايف. قبل التفعيل، أنشئ قاعدة اختبار منفصلة واختبر نسخها واسترجاعها كاملًا. نجاح pg_dump والتشفير لا يغني عن اختبار الاسترجاع.

تنزيل .backup لا يحتوي مفتاح التشفير. بعد توفير المفتاح في بيئة محلية موثوقة:

```
node scripts/decrypt-backup.js input.backup output.dump
pg_restore --list output.dump
```

الأداة ترفض الكتابة فوق ملف موجود وتزيل المخرجات الجزئية عند فشل التحقق من التشفير. استرجع بـpg_restore إلى قاعدة جديدة فقط بعد تحديد الاتصال والتحقق منه صراحةً. الاسترجاع إلى اللايف ليس ضمن هذه الميزة ويحتاج موافقة مستقلة. احذف النسخة غير المشفرة بعد انتهاء التحقق.
